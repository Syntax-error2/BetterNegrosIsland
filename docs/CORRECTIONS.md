# Private corrections and privacy requests

The project contact supplied by the maintainer is **aquraitssuport@gmail.com**. The `/corrections` page uses mailto links only; it does not collect or transmit a web form. No test message has been sent and inbox delivery has not been independently verified.

Review the private inbox regularly. Keep requests, sender information and attachments out of Git, public issues, build artifacts and public logs. Ask initially for a page/source reference and a short description, not identity documents. Any necessary verification requires a proportionate private process. Confirm provider settings, lawful criteria, access controls and a documented retention/deletion procedure with appropriate review; publishing this address does not establish those arrangements.

For a data correction, verify the original document and distinguish an upstream change from a portal presentation error. Preserve amounts, budget stage, fiscal year and uncertainty. For a privacy concern, review whether exposure should be restricted promptly while investigating; consider retained snapshots, downloads, Git history, caches and older deployments. Do not silently replace an immutable snapshot with different content under the same version. Publish a new version, or withdraw affected versions and leave an explicit unavailable state when necessary.

After a reviewed correction is published, add a minimal entry to `public/data/corrections.json`: `date` (YYYY-MM-DD), affected `version`, public `record` reference, factual `summary`, and HTTPS `source`. Never include requester identity, correspondence, private identifiers or allegations. An empty log means no published entries, not no requests. The site does not promise automatic acknowledgment or a fixed resolution period.
