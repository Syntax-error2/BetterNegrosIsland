## Outcome and root cause

All six plotted views now have visible SVG viewports, their expected nonzero marks, and exact table equivalents at the eleven requested CSS widths. Overview, Analytics and the expanded Explorer context share `KpiCard`. Budget History has explicit FY headings, selected-year header/cell highlighting, readable phone year controls, keyboard Home/End horizontal scrolling, a sticky desktop project column, separated monetary columns and 32px final-column right padding. Source actions prefer the canonical source-provided citizen page, then an approved PDF; public JSON access remains explicitly available for developers. The footer uses the supplied operator and civic initiative wording without its former pending-status sentence.

**The actual chart failure in this checkout was CSS, not missing financial data.** Recharts **3.10.1** puts its explicitly measured chart inside a zero-width/zero-height, overflow-visible sizing element. `analytics.css` applied `max-width: 100%` to both `.recharts-wrapper` and its SVG. The wrapper's percentage maximum resolved against that zero-width parent. An observed Chart A SVG was **0px wide × 300px high**, although its first bar group reported **28px × 222px** and the real chart box was about **619px wide**. Both axes and bars were clipped by the zero-width viewport. The same shared rule affected A/B/C/D/F/E.

The preceding repair had correctly changed `BarChart` to consume the same normalized `chartRows` as its `axisLabel` axes and tables. That correction is preserved. It did not resolve this subsequent CSS viewport collapse. The original browser guard counted bar rectangles and passed the broken baseline. It now also requires a nonzero SVG viewport matching the real parent width. The offending percentage constraints are removed; transient horizontal resize overflow is contained at the actual chart box with scoped `overflow: clip`. No global page overflow hiding, fake data, fixed desktop fallback width or enlarged blank plot was introduced.

Before: `before/analytics-1440.png`, `before/analytics.json`. After: `after/charts-ab-1440.png`, `after/charts-cd-1440.png`, `after/analytics-1440.png`, `after/analytics-390.png`. Screenshots were visually inspected. The normalized model and axis mapping remain essential; the strengthened viewport check closes the false-positive gap in the earlier evidence.

## API and application security review

The BetterGov.PH API is intentionally public and read-only; exposing its URL is not treated as a vulnerability. Its documentation identifies integer peso units, null semantics, candidate matches, canonical `url`/`pdf_url` fields and fair-use caching: [provider documentation](https://budget.bettergov.ph/docs). The resolver uses the returned project page rather than inventing a regional website route. General website fallbacks explicitly disclose their national scope. All new-tab dynamic links pass the central resolver and use `noopener noreferrer`. Exact API queries remain available under developer disclosures.

The existing 25-second request timeout, per-page promise cache, failed-request cache eviction, bounded pagination and four-at-a-time project fetches remain. There is no automatic retry loop or concealment proxy. Static snapshot validation remains separate from current live details; live responses now fail closed on mismatched identities, invalid units, incomplete structural fields or unsafe/coerced money. Safe asynchronous rejection prevents an invalid URL record ID from crashing the route. No acknowledgment, visitor search history or credentials are attached to API requests.

React text escaping, no unsafe HTML insertion in inspected source, CSV formula neutralization and current source provenance remain. `npm audit` reported **0 known vulnerabilities**; this is a registry advisory check, not a penetration test. Narrow built-bundle checks found no QA controls, synthetic fixtures, audit library, private-key marker or common secret-token patterns. No comprehensive secret-scanner claim is made.

The supplied CSP/security headers remain in `public/_headers`: same-origin script/font/manifest, restricted BetterGov API connection, no frames/objects, restrictive permissions and no-referrer. Inline style allowance remains necessary for React/Recharts. These files must still be verified as actual HTTP headers on the selected production host; a successful local Vite preview does not establish production header enforcement.
